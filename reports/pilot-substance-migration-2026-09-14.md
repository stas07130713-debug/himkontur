# Отчёт по пилотной миграции базы опасных грузов

Дата проверки: 14.09.2026  
Объём этапа: только UN 1017, 1005, 1050, 1824 и 1972. Остальная база не переписывалась.

## 1. Найденные источники и прежняя структура

| Набор | Назначение | Состояние |
|---|---|---|
| `public/data/dangerous-goods.tsv` | транспортный перечень UN, наименование, класс, код, № опасности | не должен быть источником физико-химических свойств |
| `dangerous-goods-index-2026.json` | связь UN/наименования с железнодорожной АК | одна АК закономерно относится к нескольким UN |
| `emergency-cards-2026.json` | текст групповых железнодорожных АК | допустим только для транспортных действий группы |
| `dangerous-goods-profiles-2026.json` | вручную созданные индивидуальные профили | всего несколько записей; ранее интерфейс мог дополнять ими групповую АК |
| `emergency-cards.json` | прежний совмещённый набор | устаревающий слой совместимости |

## 2. Места смешения данных

1. `build-structured-emergency-cards.mjs` создаёт индекс UN → групповая АК; сама эта связь верна, но прежняя экранная модель располагала групповой текст рядом с индивидуальным описанием без строгой границы.
2. `emergencyCardLookup.ts` возвращает одновременно транспортную запись, групповую АК и необязательный индивидуальный профиль. Это облегчало ошибочную подстановку групповых формулировок в свойства вещества.
3. `DangerousGoodsPanel.tsx` исторически имел цепочку резервных данных «индивидуальный профиль → карточка», из-за чего текст группы мог восприниматься как характеристика выбранного UN.
4. Формула вещества и расчётные параметры АХОВ хранятся отдельно от транспортного перечня. Связь по названию без устойчивых идентификаторов создаёт риск смешения химического вещества, товарной формы и транспортной записи.
5. Старый набор профилей не хранит источник и статус качества для каждого поля, поэтому невозможно автоматически отличить подтверждённое значение от наследованного текста.

## 3. Реализованная модель пилота

Созданы отдельные сущности: `ChemicalEntity`, `ProductForm`, `TransportEntry`, `EmergencyProfile` и `TransportInstructions`. Каждое содержательное поле имеет список источников, статус качества и дату проверки.

Поток публикации разделён на три слоя:

1. `raw` — неизменяемый снимок исходной транспортной строки;
2. `normalized` — нормализованная связанная запись;
3. `published` — только запись, прошедшая валидатор и имеющая исходный снимок.

Групповая железнодорожная АК хранится в `TransportInstructions.rail` и не может быть источником `EmergencyProfile.mainProperties`. Интерфейс для пилотных UN читает только слой `published`.

## 5. План продолжения после одобрения пилота

1. Зафиксировать справочник официальных источников и допустимые типы источников для каждого поля.
2. Импортировать следующую ограниченную партию в `raw`, не изменяя старые опубликованные записи.
3. Нормализовать химическое вещество, форму продукта и транспортную запись раздельно.
4. Выполнить предметную проверку индивидуального профиля и конфликтов источников.
5. Прогнать автоматический валидатор и ручной просмотр карточки в светлой/тёмной теме.
6. Публиковать только прошедшие записи; отклонённые сохранять с причинами.
7. После полной миграции отключить устаревшую резервную подстановку групповой АК.

## 6. Ограничения текущего этапа

- Для непилотных UN продолжает работать прежняя база; она не объявляется проверенной новой моделью.
- Специальные положения ADR пока не импортированы в пилот и показаны как пустое подтверждённое транспортное поле; перед промышленной публикацией их следует сверить построчно.
- Полноценная спутниковая подложка без интернета требует заранее скачать разрешённый пакет тайлов выбранной территории. Сейчас приложение кэширует уже просмотренные тайлы и при отсутствии сети показывает автономную координатную подложку; это не выдаётся за спутниковую карту.

## 7. Дополнительная проверка интерфейса

- Ручной поиск и распознавание фотографии сделаны взаимоисключающими: начало работы одним способом очищает неподтверждённый результат другого.
- Распознанные значения Кемлера и UN редактируются непосредственно в оранжевой табличке; несколько найденных табличек остаются отдельным списком.
- Точный запрос имеет приоритет над частичным совпадением: запрос «Хлор» первым возвращает UN 1017, а не вещество, лишь содержащее слово «хлор» в длинном названии.
- До подтверждения поиска или маркировки правая аварийная карточка не отображается.
- В мобильной версии после ввода идут результаты расчёта, затем карта и контрольные точки; однопальцевое вертикальное движение прокручивает страницу.
- Лишняя кнопка перехода к расчёту зоны из аварийной карточки удалена; рабочие вкладки визуально разделены.
