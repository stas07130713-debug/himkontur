# Аудит стабильности и синхронизации ХИМКОНТУР

Дата проверки: 16.10.2026  
Проверенная версия исходного проекта: 0.3.16.

## 1. Как система работает сейчас

- Браузерная версия публикуется через GitHub Pages после отправки изменений в ветку `main`.
- Windows и Android получают новый программный код только из нового GitHub Release.
- Windows автоматически проверяет последний выпуск, загружает его и предлагает установку.
- Android проверяет последний выпуск, предлагает пользователю загрузить APK и открыть системную установку. Полностью скрытая установка APK невозможна из-за правил безопасности Android.
- Карта района выезда хранится в общей базе GitHub Gist и дополнительно кэшируется в `localStorage` каждого устройства для автономной работы.
- Административное изменение сразу сохраняется локально и автоматически отправляется в общую базу. Другие устройства проверяют новую редакцию при запуске, возвращении из фона и каждые 30 секунд.
- GitHub Actions каждые 10 минут сохраняет резервную копию общей базы в `public/data/district-map.json` основного репозитория.
- Текущий пароль администратора `1234` находится в клиентском коде. Это только защита от случайного входа, а не полноценная безопасность.

Вывод: изменения карточек, координат и актов передаются на другие устройства без выпуска новой версии приложения. Новый релиз требуется только для изменения программного кода и встроенных ресурсов.

## 2. Реализованная минимальная схема

Нужно отделить **данные** от **программного кода**.

1. Администратор открывает браузерную версию на любом компьютере и вводит пароль.
2. После каждого сохранения программа увеличивает редакцию и обновляет отдельный публичный GitHub Gist с файлом `district-map.json`.
3. Ключ GitHub имеет только разрешение `gist`; он не может менять исходный код или выпускать релизы. В комплекте он хранится в зашифрованном виде и расшифровывается в памяти после ввода общего административного пароля.
4. Браузерная, Windows- и Android-версии при запуске, возвращении из фона и каждые 30 секунд запрашивают маленький JSON-файл актуальной редакции.
5. Если редакция новее, карточки и координаты обновляются автоматически. Пользователь ничего не переустанавливает и не подтверждает.
6. Последняя корректная копия остаётся на устройстве и используется без интернета. После восстановления связи выполняется синхронизация.
7. У Gist сохраняется собственная история редакций, а основной репозиторий получает автоматическую резервную копию каждые 10 минут.

### Что обновляется без релиза

- здания, цеха, отделения и участки;
- координаты и карточки объектов;
- пожарные гидранты и их состояние;
- результаты применения акта проверки;
- документы предварительного планирования;
- пользовательские примечания.

### Для чего всё ещё нужен новый релиз

- изменение расчётных алгоритмов;
- изменение интерфейса или логики приложения;
- новая версия OCR;
- изменение формата данных, которое старые приложения не понимают;
- новые встроенные офлайн-карты и большие справочники;
- исправления Windows- или Android-оболочки.

## 3. Стоимость и эксплуатация

- Для публичного репозитория GitHub Pages и GitHub Actions можно использовать в рамках GitHub Free.
- Отдельный сервер и платная инфраструктура для текущего режима не требуются.
- Номер редакции перед записью сверяется с общей базой; резервная копия создаётся автоматически.

## 5. Найденные ограничения и риски

### Высокий приоритет

Критических функциональных ошибок по результатам автоматических проверок не найдено.

### Средний приоритет

1. Общий пароль `1234` и зашифрованный ключ с правом `gist` находятся на стороне клиента. Это соответствует заявленной защите только от случайного входа, но не защищает от целевой атаки. При повышении требований нужно перенести ключ в серверный секрет.
2. Веб/PWA-комплект предварительно кэширует около 230 МБ. Это обеспечивает автономные карты и OCR, но первая установка и обновление браузерной версии могут быть долгими на медленной связи.
3. Основной JavaScript-пакет и модуль формирования отчётов крупные. Они работают, но в дальнейшем желательно разделить их на дополнительные загружаемые части.
4. Автоматическая погода зависит от внешних сервисов. В Windows и Android первым используется российский ProjectEOL через нативный запрос, затем резервные сервисы. Необходим периодический контроль на реальном устройстве без VPN.
5. Справочник опасных грузов шире массива официальных аварийных карточек: для части транспортных записей официальная карточка отсутствует. Программа корректно не выдумывает такие сведения, но покрытие базы следует продолжать расширять.

### Низкий приоритет

1. Android-сборка использует один устаревающий системный вызов определения версии для старых Android; сборка проходит, функциональной ошибки нет.
2. Инструмент экранного аудита иногда получал дробное смещение липкой мобильной шапки на несколько виртуальных пикселей. На снимках реального переполнения нет; допуск теста скорректирован без изменения интерфейса.

## 6. Исправления, внесённые во время аудита

- чтение общей карты дополнено постоянными адресами GitHub Pages и raw-файла с резервом через GitHub API;
- при одинаковом номере редакции теперь учитывается время публикации;
- координаты загружаемых объектов проверяются на конечность и допустимый диапазон;
- Android больше не должен зависеть от `api.github.com` при проверке обновлений: релиз формирует маленький `latest-android.json` и отдаёт его через постоянную ссылку последнего выпуска;
- добавлены тесты порядка редакций общей карты;
- исправлен адрес запуска функциональной проверки карты района выезда;
- устранён ложный сбой экранной матрицы из-за дробного округления мобильного viewport.
- добавлена двусторонняя синхронизация карты через отдельный GitHub Gist;
- добавлено автоматическое получение новой редакции всеми устройствами без переустановки;
- добавлена резервная копия базы в основной репозиторий каждые 10 минут;
- в строке состояния добавлены дата базы и состояние синхронизации;
- подключена новая глянцевая иконка линейки.

## 7. Итоговая оценка

Программа пригодна для контролируемой эксплуатации: расчёты, справочники, OCR, карты, импорт акта, синхронизация общей карты и нативные сборки проходят проверки. Административная карта теперь является общей базой для браузера, Windows и Android. Текущую защиту следует считать упрощённой; для режима с конфиденциальными данными или строгим разграничением прав потребуется серверная авторизация.

ХИМКОНТУР является системой поддержки принятия решений. Для реальных аварийных работ результаты должны проверяться ответственным специалистом и применяться вместе с действующими нормативными документами и оперативными данными.
